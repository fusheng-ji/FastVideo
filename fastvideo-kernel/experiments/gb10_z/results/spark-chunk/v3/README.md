# Chunked AdamW validation v3: smoke launch blocked

Based on `spark/gb10-chunk-validation-v2` at
`49ed5c8f91a5207852c180d8fc37485156a40718`. This directory appends evidence;
all v2 failure records and their checksum manifest are retained unchanged.
Prerequisite verification and CPU self-checks were not repeated.

## Outcome and stop condition

One fresh smoke attempt was scheduled for 8192 tokens, chunk 0, seed 1000 and
one update through the production YAML entrypoint. The launcher stopped the
known compatibility service and released the manual training hold, then found
`VLLM::EngineCore` still occupying the GPU. It exited with code 2 before
starting telemetry or Python training. No output directory for training was
created; the launcher receipt uses a new local directory.

No training update, loss, gradient norm or parameter hash was produced.
This is a launch failure, not a loss or optimizer correctness failure.
The competing process was not killed and the run was not retried. Both paused
services were restored to their original active state. The thermal guard
remained active. Duty and Ollama were inactive before the attempt.

The smoke gate did not pass, so the 8192 paired reproduction, 31200 phase
attribution, 200-step consistency test and optional chunk sweep were not run.
There is no accepted reproduction result, phase attribution, bitwise-equality
result or best chunk size from v3.

## Tracker configuration and observation

Every new run configuration generated by `chunk_entry_preflight.py` explicitly
sets `training.tracker.trackers: [none]`. No W&B credentials were provided or
requested. The intended sanitized one-step YAML is `smoke-config.yaml`.
The blocked launch does not verify that tracker initialization now succeeds.

`chunk_observer.py` is an experiment-only YAML callback. It records each loss,
gradient norms emitted by the existing clipping callback, initial/post-update
SHA256 hashes for the 825 parameter tensors and CUDA peak counters. It checks
that at least one parameter changed after the update. It does not replace the
optimizer, training method or production loop. This callback was syntax-checked
but was not reached by the blocked smoke launch; it has no GPU acceptance claim.
No production files, optimizer implementation or kernel defaults changed.
